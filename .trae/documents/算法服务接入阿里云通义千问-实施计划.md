# 接入阿里云通义千问：新建独立算法服务（algorithm-service）

## Context（为什么做）

当前系统的「AI 解读」链路是：前端 → 后端 FastAPI → `POST {ALGO_BASE_URL}/llm/analyze` → **降级到规则 mock**。

原因：`ALGO_BASE_URL`（`backend/app/core/config.py` L56-58）指向 `http://localhost:8100`，但该服务在本仓库中并不存在（开发文档 §2.6 提到的 `algorithm-mock/` 目录也没建）。因此舌诊/面诊/问诊/合参四处的「AI 分析」实际都跑的是 `*_mock_analysis.py` 的确定性规则，`model_version` 恒为 `*_mock_v1`。

目标：新建一个**独立算法服务**（FastAPI，监听 `:8100`），实现契约 `POST /llm/analyze`，内部调用**阿里云通义千问（DashScope OpenAI 兼容接口）**生成真实的可读结论。后端与前端**零改动**（契约已冻结，省事且降级机制天然复用）。

## 架构与调用链

```
前端           后端 FastAPI                        算法服务 :8100            阿里云 DashScope
─────────      ──────────────────────────         ────────────────         ─────────────────
T4 触发   ──▶  BackgroundTasks                   POST /llm/analyze   ──▶  POST {base}/chat/completions
               └ _call_algo() ──HTTP──────────▶  └ 组 prompt             └ qwen-plus
                                                    └ 解析/校验 JSON
T5 轮询   ◀──  写回 analysis 记录 ◀─────────────    返回 {data:{...}}
               （失败/超时 → *_mock_analysis 降级）
```

## 关键实现要点

### 1. LLM 客户端（DashScope OpenAI 兼容）

- `DASHSCOPE_BASE_URL` 默认 `https://dashscope.aliyuncs.com/compatible-mode/v1`
- `POST {base}/chat/completions`，鉴权 `Authorization: Bearer <DASHSCOPE_API_KEY>`
- 请求体：`{"model": <模型>, "temperature": 0.2, "messages":[...], "response_format": {"type":"json_object"}}`
- 默认模型 `qwen-plus`（可换 `qwen-max`/`qwen-turbo`），由 `LLM_MODEL` 配置
- 429/5xx 重试 1 次；其余异常向上抛 → `main.py` 映射 503，交由后端降级
- **不引入 openai SDK**，复用 `httpx`，依赖最小化

### 2. Prompt（`prompts.py`，四模块各一个 builder）

统一约定（写在 system 末尾）：只输出一个 JSON 对象，不含解释/Markdown/代码块；`confidence` 为 0~1 小数；结论仅供参考、非诊断依据。文末含 "JSON" 关键词以满足 json_object 前置条件。

- `tongue`：输入 `features[{name,label,confidence}]`（tongue_color/coating_color/coating_texture/tongue_shape）→ 输出 `tongue_summary, main_syndrome, secondary_syndromes, treatment_principles, recommendations`
- `face`：同上，输入 face_color/luster/acne/spots，输出 `face_summary` + 其余
- `inquiry`：输入 `answers, missing_items` → 输出 `symptoms_summary` + 其余（缺项时下调 confidence）
- `fusion`：输入 `snapshot, conflicts, missing_modules, overall_confidence` → 输出 `conclusions[{text,confidence}], syndrome_points[str], suggestions[{category,text}]`（存在 conflicts 时须显式提示权重下调）

### 3. 输出健壮性（`parsing.py`）

- 解析：先 `json.loads`；失败去 ```json 围栏/取首个 `{...}`；再失败截取首个 `{` 到末个 `}`；仍失败 → 抛错（后端降级）
- 校验：pydantic 模型 `confidence: float = Field(ge=0, le=1)` + validator 钳制；`main_syndrome` 缺 name → `平和质倾向/0.5`；`recommendations/suggestions` 缺 `category|text` → 丢弃该项；summary 空 → `"暂无"`
- `model_version` 返回 `f"{module}_llm_v1_{LLM_MODEL}"`（关键：非 `*_mock_v1`，用于确认未降级）

### 4. 配置（`algorithm-service/.env`）

```
DASHSCOPE_API_KEY=sk-xxxx        # 用户自行填入（不入库）
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen-plus
LLM_TIMEOUT_SECONDS=60
```
`.env.example` 只留占位说明；真实密钥由用户写入本地 `.env`（已被 `.gitignore` 忽略）。

## 验证方案（端到端）

1. `python run.py --force` → 终端出现「算法服务」状态行与可点击网址
2. `curl http://localhost:8100/health` → `{"status":"ok","model":"qwen-plus","key_configured":true}`
3. 直连契约：`POST http://localhost:8100/llm/analyze`（module=tongue）→ 字段齐全、`model_version` 含 `qwen-plus`（**非** `tongue_mock_v1`）
4. 全链路：登录 → 舌诊 上传→提取→特征→触发 AI→轮询完成 → 报告结论为真实大模型产物；面诊/问诊/合参同理
5. 降级负向测试：停掉算法服务或故意填错 key → 结果回落到 `*_mock_v1`，链路不中断
6. 现有后端测试不受影响（`tests/*` 已 monkeypatch `_call_algo`）

## 风险与注意

- **超时竞速**：LLM 单次可能接近 60s。后端 `ALGO_TIMEOUT_SECONDS` 若仍为 60，会与算法服务的 LLM 超时同时触发，后端先超时→无谓降级。故把它提到 90，让算法服务先干净返回 503/正常结果，后端再决定成功或降级。（前端轮询总预算约 115s，90s 在其内）
- **密钥**：`DASHSCOPE_API_KEY` 仅落本地 `.env`（已 gitignore）；不要写进代码或提交。
- **地域**：DashScope key 与地域绑定，跨地域会 401；默认用北京 endpoint。
- **模型输出**：`json_object` 需 prompt 含 "JSON" 字样；不要设过小 `max_tokens`（截断→非法 JSON）。
